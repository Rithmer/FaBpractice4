# ТехМаркет - Интернет-магазин техники

Полноценное full-stack приложение интернет-магазина техники с авторизацией, JWT, refresh-токенами, ролевой моделью доступа (RBAC), PWA-функциями и push-уведомлениями.

## Что реализовано по практикам

### Практика 13. Service Worker
**Для чего реализовано:** чтобы приложение имело базовый офлайн-функционал и могло работать с кэшем ресурсов.

1. Добавил Service Worker: сайт начал сохранять важные файлы локально и быстрее открываться повторно.
2. Добавил его регистрацию при запуске: механизм включается автоматически, без действий пользователя.
3. Настроил жизненный цикл и уведомления: кэш обновляется корректно, а push и действия в уведомлениях обрабатываются стабильно.

### Практика 14. Web App Manifest
**Для чего реализовано:** чтобы приложение можно было установить как PWA и корректно отображать иконки/тему.

1. Добавил манифест приложения: сайт можно установить как отдельное приложение.
2. Добавил набор иконок: приложение выглядит аккуратно на телефоне и компьютере.
3. Подключил нужные мета-теги: корректно отображаются тема, иконка и запуск в PWA-режиме.

### Практика 15. HTTPS + App Shell
**Для чего реализовано:** чтобы соблюсти архитектуру App Shell и стабильную загрузку интерфейса в PWA-формате.

1. Собрал устойчивый каркас интерфейса: пользователь сразу видит структуру страницы, даже при медленной сети.
2. Добавил кэширование каркаса: загрузка стала заметно быстрее при повторных открытиях.
3. Разделил dev и production-поведение: в разработке ничего не мешает обновлениям, в проде работает полноценный PWA-режим.

### Практика 16. WebSocket + Push
**Для чего реализовано:** чтобы получать события в реальном времени и системные уведомления.

1. Добавил связь в реальном времени: изменения на сайте приходят сразу, без ручного обновления страницы.
2. Добавил подписку на push: пользователь может получать системные уведомления от приложения.
3. Сделал управление push в интерфейсе: уведомления можно включать и отключать одной кнопкой.

### Практика 17. Детализация Push
**Для чего реализовано:** чтобы интегрировать уведомления в доменную логику магазина (не "заметки", а отслеживание товаров).

1. Добавил отслеживание товара по названию: пользователь вводит, что ждет, и приложение следит за появлением.
2. Сделал "умное" сравнение названий: разные варианты ввода (например, `Iphone17` и `iPhone 17`) распознаются как одно и то же.
3. Настроил срабатывание при появлении товара: уведомление приходит и при создании, и при обновлении карточки товара.
4. Разделил тип уведомления по контексту:
   - если пользователь в приложении — показывается внутренняя плашка;
   - если вкладка скрыта — приходит системное push-уведомление.
5. Добавил автоочистку отслеживания после срабатывания: пользователю не нужно удалять его вручную.

## Роли в системе

- `guest` - неавторизованный пользователь.
- `user` - просмотр товаров + создание отслеживаний.
- `seller` - просмотр + создание/редактирование товаров + создание отслеживаний.
- `admin` - полный доступ к товарам + управление пользователями + создание отслеживаний.

## API маршруты и доступ

### Аутентификация

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/auth/register` | POST | guest | Регистрация пользователя |
| `/api/auth/login` | POST | guest | Вход, выдача access/refresh токенов |
| `/api/auth/refresh` | POST | guest | Обновление пары токенов |
| `/api/auth/me` | GET | user/seller/admin | Получение текущего пользователя |

### Пользователи (только admin)

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/users` | GET | admin | Список пользователей |
| `/api/users/:id` | GET | admin | Пользователь по id |
| `/api/users/:id` | PUT | admin | Обновление email/имени/фамилии/роли |
| `/api/users/:id` | DELETE | admin | Блокировка пользователя |

### Товары

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/products` | GET | user/seller/admin | Список товаров |
| `/api/products` | POST | seller/admin | Создание товара + триггер проверки отслеживаний |
| `/api/products/:id` | GET | user/seller/admin | Товар по id |
| `/api/products/:id` | PUT | seller/admin | Обновление товара + триггер проверки отслеживаний |
| `/api/products/:id` | DELETE | admin | Удаление товара |

### Push и отслеживания

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/push/public-key` | GET | auth | Публичный VAPID-ключ |
| `/api/push/subscribe` | POST | auth | Сохранение push-подписки |
| `/api/push/unsubscribe` | POST | auth | Удаление push-подписки |
| `/api/reminders` | POST | auth | Создание отслеживания товара |
| `/api/reminders` | GET | auth | Получение активных отслеживаний пользователя |
| `/api/reminders/dismiss?reminderId=...` | POST | auth | Удаление отслеживания/уведомления |

## Как запустить проект

### 1. Требования

- Node.js 18+ (рекомендуется актуальная LTS)
- npm

### 2. Запуск backend

```bash
cd backend
npm install
node server.js
```

Backend будет доступен по адресу: `http://localhost:3000`  
Swagger UI: `http://localhost:3000/api-docs`

### 3. Запуск frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend будет доступен по адресу: `http://localhost:3001`

### 4. Сборка frontend

```bash
cd frontend
npm run build
```
