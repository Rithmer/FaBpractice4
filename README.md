# ТехМаркет - Интернет-магазин техники

Полноценное full-stack приложение интернет-магазина техники с авторизацией, JWT, refresh-токенами, ролевой моделью доступа (RBAC) и клиентской частью на React.

## Что реализовано по практикам

### Практика 7. Базовые методы аутентификации
**Для чего реализовано:** чтобы обеспечить безопасную регистрацию и вход пользователя, а также хранить пароли только в хешированном виде.

- Добавлены маршруты регистрации и входа.
- Реализовано хеширование паролей через `bcrypt`.
- Пароль сохраняется только как `passwordHash`.

### Практика 8. JWT и защищенные маршруты
**Для чего реализовано:** чтобы после входа пользователь получал токен доступа и мог обращаться к защищенным ресурсам API.

- При входе выдается `accessToken`.
- Добавлен защищенный маршрут `GET /api/auth/me`.
- Реализована проверка `Authorization: Bearer <token>` в middleware.

### Практика 9. Refresh-токены
**Для чего реализовано:** чтобы автоматически продлевать сессию без повторного ввода логина и пароля после истечения access-токена.

- Добавлен `refreshToken`.
- Реализован `POST /api/auth/refresh`.
- Настроена ротация refresh-токенов (старый токен инвалидируется, выдается новая пара).

### Практика 10. Хранение токенов на фронтенде
**Для чего реализовано:** чтобы связать клиентскую часть с API и автоматизировать авторизацию в интерфейсе.

- Реализованы страницы регистрации и входа на React.
- Токены сохраняются в `localStorage`.
- Настроены Axios interceptors для:
  - автоматической подстановки `accessToken` в запросы;
  - автоматического обновления токенов при ответе `401`.

### Практика 11. Управление доступом на основе ролей (RBAC)
**Для чего реализовано:** чтобы разграничить права пользователей по ролям и ограничить доступ к операциям API.

- Добавлены роли `user`, `seller`, `admin`.
- Реализованы ограничения доступа к маршрутам по ролям.
- Добавлено администрирование пользователей:
  - просмотр списка;
  - редактирование данных и роли;
  - блокировка пользователей.

### Практика 12. Подготовка к контрольной работе №2
**Для чего реализовано:** чтобы завершить интеграцию всех частей приложения, проверить работоспособность и оформить итоговую документацию.

- Проведена проверка работы backend и frontend.
- Подготовлен итоговый `README.md` с описанием функционала и инструкциями запуска.

## Роли в системе

- `guest` - неавторизованный пользователь.
- `user` - просмотр товаров.
- `seller` - просмотр + создание/редактирование товаров.
- `admin` - полный доступ к товарам + управление пользователями.

## API маршруты и доступ

### Аутентификация

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/auth/register` | POST | guest | Регистрация пользователя |
| `/api/auth/login` | POST | guest | Вход, выдача access/refresh токенов |
| `/api/auth/refresh` | POST | guest | Обновление пары токенов |
| `/api/auth/me` | GET | user/seller/admin | Получение текущего пользователя |

### Пользователи (только admin)

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/users` | GET | admin | Список пользователей |
| `/api/users/:id` | GET | admin | Пользователь по id |
| `/api/users/:id` | PUT | admin | Обновление email/имени/фамилии/роли |
| `/api/users/:id` | DELETE | admin | Блокировка пользователя |

### Товары

| Маршрут | Метод | Доступ | Описание |
|---|---|---|---|
| `/api/products` | GET | user/seller/admin | Список товаров |
| `/api/products` | POST | seller/admin | Создание товара |
| `/api/products/:id` | GET | user/seller/admin | Товар по id |
| `/api/products/:id` | PUT | seller/admin | Обновление товара |
| `/api/products/:id` | DELETE | admin | Удаление товара |

## Функциональность фронтенда

- Авторизация и регистрация пользователей.
- Автоматическое восстановление сессии через `refreshToken`.
- Каталог товаров:
	- поиск по названию и описанию;
	- фильтрация по категории;
	- просмотр карточки товара и деталей.
- Управление товарами по ролям (создание/редактирование/удаление).
- Вкладка управления пользователями для администратора.

## Как запустить проект

### 1. Требования

- Node.js 18+ (рекомендуется актуальная LTS)
- npm

### 2. Запуск backend

```bash
cd backend
npm install
node server.js
```

Backend будет доступен по адресу: `http://localhost:3000`  
Swagger UI: `http://localhost:3000/api-docs`

### 3. Запуск frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend будет доступен по адресу: `http://localhost:3001`

### 4. Сборка frontend

```bash
cd frontend
npm run build
```
